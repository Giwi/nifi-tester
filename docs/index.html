NiFi Tester

YAML pipeline deployment & testing for Apache NiFi

💻 GitHub

Overview

NiFi Tester is a Java client library and CLI tool for deploying, testing, and managing Apache NiFi dataflows using declarative YAML configuration. Define your entire flow — processors, connections, controller services, ports, funnels, and nested process groups — in a single portable YAML file, and deploy it to any NiFi instance with one command.

Built on auto-generated REST clients from NiFi's OpenAPI spec, with YAML-to-NiFi conversion, pipeline validation, dry-run mode, JUnit 5 integration, and reusable YAML templates.

Features

📄

YAML Pipeline Definition

Define processors, connections, controller services, ports, funnels, and nested process groups in a single YAML file.

🎮

CLI Deployment

Deploy pipelines with one command: nifi-tester --file pipeline.yaml

⚙️

Java API

Programmatic access via PipelineManager with try-with-resources support.

🚧

Dry-Run Mode

Validate YAML syntax and references without deploying to NiFi.

📤

Export to YAML

Export deployed process groups back to YAML format (--export).

🔄

NiFi JSON Conversion

Convert existing NiFi JSON flow definitions to YAML (--convert).

✅

Pipeline Validation

Validates references, types, and structure before deployment.

📋

YAML Templates

Save and load reusable pipeline snippets (--save-template / --load-template).

🔍

Interactive Mode

Explore NiFi: list groups, show group details (--list-groups, --show-group).

🧪

JUnit 5 Integration

Use @NiFiConnection annotation for integration tests.

🔁

Automatic Retry

Built-in retry logic for transient API failures.

💥

AutoCloseable

Use with try-with-resources for automatic cleanup of deployed resources.

Quick Start

Build

./gradlew build

Deploy a pipeline

./gradlew run --args='--url https://localhost:8443/nifi-api --user admin --pass admin1234567 --file pipeline.yaml'

Or use the CLI directly

./build/install/nifi-tester/bin/nifi-tester --url https://localhost:8443/nifi-api --file pipeline.yaml

Convert a NiFi export to YAML

./gradlew run --args='--convert nifi-export.json --output pipeline.yaml'

Validate without deploying (dry-run)

./gradlew run --args='--file pipeline.yaml --dry-run'

Sample Pipelines

GenerateFlowFile + LogAttribute

A minimal pipeline that generates flow files with custom content and logs them.

# sample-generate-pipeline.yaml
name: Sample GenerateFlowFile Pipeline
description: A simple pipeline that generates flow files with custom content
parentGroupId: root

processors:
  - name: GenerateFlowFile
    type: org.apache.nifi.processors.standard.GenerateFlowFile
    x: 200
    y: 100
    schedulingStrategy: TIMER_DRIVEN
    schedulingPeriod: "5 sec"
    properties:
      File Size: 1KB
      Custom Text: Hello World from NiFi Test Pipeline

  - name: LogAttribute
    type: org.apache.nifi.processors.standard.LogAttribute
    x: 500
    y: 100
    properties:
      Log Level: info
      Log Prefix: "Processed: "
    autoTerminatedRelationships:
      - success

connections:
  - name: Success Relationship
    sourceId: ${GenerateFlowFile}
    destinationId: ${LogAttribute}
    relationships:
      - success

Kafka Pipeline

Consume from Kafka, parse JSON, validate records, route valid/invalid messages, and publish to different topics.

# kafka-pipeline.yaml
name: Kafka Pipeline Sample
parentGroupId: root

processors:
  - name: ConsumeKafka
    type: org.apache.nifi.processors.kafka.ConsumeKafka
    x: 100
    y: 100
    properties:
      Kafka Brokers: localhost:9092
      Topic(s): input-topic
      Group ID: nifi-consumer-group

  - name: ParseJSON
    type: org.apache.nifi.processors.standard.SplitJson
    x: 350
    y: 100

  - name: ValidateRecord
    type: org.apache.nifi.processors.standard.ValidateRecord
    x: 600
    y: 100

  - name: RouteOnAttribute
    type: org.apache.nifi.processors.standard.RouteOnAttribute
    x: 850
    y: 100
    properties:
      '${record.type:equals("VALID")}': VALID
      '${record.type:equals("INVALID")}': INVALID

  - name: PublishValid
    type: org.apache.nifi.processors.kafka.PublishKafka
    x: 1100
    y: 50
    properties:
      Kafka Brokers: localhost:9092
      Topic Name: valid-topic

  - name: PublishInvalid
    type: org.apache.nifi.processors.kafka.PublishKafka
    x: 1100
    y: 150
    properties:
      Kafka Brokers: localhost:9092
      Topic Name: invalid-topic

  - name: LogInvalid
    type: org.apache.nifi.processors.standard.LogAttribute
    x: 850
    y: 250
    autoTerminatedRelationships:
      - success

connections:
  - sourceId: ${ConsumeKafka}
    destinationId: ${ParseJSON}
    relationships: [success]
  - sourceId: ${ParseJSON}
    destinationId: ${ValidateRecord}
    relationships: [split]
  - sourceId: ${ValidateRecord}
    destinationId: ${RouteOnAttribute}
    relationships: [valid]
  - sourceId: ${RouteOnAttribute}
    destinationId: ${PublishValid}
    relationships: [VALID]
  - sourceId: ${RouteOnAttribute}
    destinationId: ${PublishInvalid}
    relationships: [INVALID]
  - sourceId: ${RouteOnAttribute}
    destinationId: ${LogInvalid}
    relationships: [unmatched]
  - sourceId: ${ConsumeKafka}
    destinationId: ${LogInvalid}
    relationships: [failure]

controllerServices:
  - name: SchemaRegistry
    type: org.apache.nifi.confluent.SchemaRegistry
    properties:
      Schema Registry URLs: http://localhost:8081

File Ingestion Pipeline

Monitor a directory for CSV files, parse them, validate records, route valid data to a database and invalid data to a separate directory.

# file-ingestion-pipeline.yaml
name: File Ingestion Pipeline
parentGroupId: root

processors:
  - name: ListFiles
    type: org.apache.nifi.processors.standard.ListFile
    x: 100
    y: 100
    properties:
      Input Directory: /data/input
      File Filter: ".*\\.csv"

  - name: FetchFile
    type: org.apache.nifi.processors.standard.FetchFile
    x: 350
    y: 100

  - name: ParseCSV
    type: org.apache.nifi.processors.standard.ConvertRecord
    x: 600
    y: 100

  - name: ValidateData
    type: org.apache.nifi.processors.standard.ValidateRecord
    x: 850
    y: 100

  - name: RouteValid
    type: org.apache.nifi.processors.standard.RouteOnAttribute
    x: 1100
    y: 100

  - name: PutToDatabase
    type: org.apache.nifi.processors.standard.PutDatabaseRecord
    x: 1350
    y: 50

  - name: MoveInvalid
    type: org.apache.nifi.processors.standard.PutFile
    x: 1350
    y: 150

  - name: ArchiveFiles
    type: org.apache.nifi.processors.standard.PutFile
    x: 350
    y: 250
    properties:
      Directory: /data/archive

connections:
  - sourceId: ${ListFiles}
    destinationId: ${FetchFile}
    relationships: [success]
  - sourceId: ${FetchFile}
    destinationId: ${ParseCSV}
    relationships: [success]
  - sourceId: ${ParseCSV}
    destinationId: ${ValidateData}
    relationships: [success]
  - sourceId: ${ValidateData}
    destinationId: ${RouteValid}
    relationships: [valid]
  - sourceId: ${RouteValid}
    destinationId: ${PutToDatabase}
    relationships: [VALID]
  - sourceId: ${RouteValid}
    destinationId: ${MoveInvalid}
    relationships: [INVALID]
  - sourceId: ${ListFiles}
    destinationId: ${ArchiveFiles}
    relationships: [failure]
  - sourceId: ${FetchFile}
    destinationId: ${ArchiveFiles}
    relationships: [failure]
  - sourceId: ${ParseCSV}
    destinationId: ${ArchiveFiles}
    relationships: [failure]
  - sourceId: ${ValidateData}
    destinationId: ${ArchiveFiles}
    relationships: [failure]

controllerServices:
  - name: CSVReader
    type: org.apache.nifi.csv.CSVReader
  - name: JSONWriter
    type: org.apache.nifi.json.JsonRecordSetWriter
  - name: DBService
    type: org.apache.nifi.dbcp.DBCPConnectionPool
    properties:
      Database Connection URL: jdbc:mysql://localhost:3306/mydb

Error Handling Pipeline

Retry logic with failure routing — retries failed SQL queries up to 2 times before moving to a dead-letter queue.

# error-handling-pipeline.yaml
name: Error Handling Pipeline
parentGroupId: root

processors:
  - name: ProcessData
    type: org.apache.nifi.processors.standard.ExecuteSQL
    x: 400
    y: 100

  - name: CheckRetryCount
    type: org.apache.nifi.processors.standard.RouteOnAttribute
    x: 650
    y: 100
    properties:
      '${retry.count:equals("0")}': FIRST_RETRY
      '${retry.count:equals("1")}': SECOND_RETRY
      '${retry.count:gt(1)}': MAX_RETRIES_REACHED

  - name: WaitBeforeRetry
    type: org.apache.nifi.processors.standard.ControlRate
    x: 650
    y: 50

  - name: IncrementRetry
    type: org.apache.nifi.processors.standard.UpdateAttribute
    x: 650
    y: 200
    properties:
      retry.count: "${retry.count:plus(1)}"

  - name: MoveToFailureQueue
    type: org.apache.nifi.processors.standard.PutFile
    x: 900
    y: 200
    properties:
      Directory: /data/failed

  - name: OnSuccess
    type: org.apache.nifi.processors.standard.LogAttribute
    x: 400
    y: 250
    autoTerminatedRelationships:
      - success

connections:
  - sourceId: ${ProcessData}
    destinationId: ${CheckRetryCount}
    relationships: [failure]
  - sourceId: ${ProcessData}
    destinationId: ${OnSuccess}
    relationships: [success]
  - sourceId: ${CheckRetryCount}
    destinationId: ${WaitBeforeRetry}
    relationships: [FIRST_RETRY, SECOND_RETRY]
  - sourceId: ${WaitBeforeRetry}
    destinationId: ${IncrementRetry}
    relationships: [success]
  - sourceId: ${IncrementRetry}
    destinationId: ${CheckRetryCount}
    relationships: [success]
  - sourceId: ${CheckRetryCount}
    destinationId: ${MoveToFailureQueue}
    relationships: [MAX_RETRIES_REACHED]

Java API

Basic usage

import org.giwi.nifi.tester.PipelineManager;

// Deploy a pipeline from YAML
PipelineManager tester = new PipelineManager(
    "http://localhost:8080/nifi-api",
    "admin",
    "password"
);

tester.setDryRun(true);  // validate without deploying

PipelineManager.PipelineManagerResult result = tester.deployPipeline(
    new java.io.File("pipeline.yaml"),
    "root"
);

AutoCloseable (try-with-resources)

try (PipelineManager tester = new PipelineManager(url, username, password)) {
    PipelineManager.PipelineManagerResult result =
        tester.deployPipeline(yamlFile, "root");
    if (result.isSuccess()) {
        System.out.println("Created: " + result.getProcessGroupId());
    }
}
// Auto-closes and cleans up deployed resources

YAML conversion

PipelineConverter converter = new PipelineConverter();

// YAML file to NiFi API-compatible map
java.util.Map<String, Object> result =
    converter.convertFromYaml(new java.io.File("pipeline.yaml"));

// NiFi JSON export to YAML
converter.convertToYaml(new java.io.File("nifi-export.json"),
                        new java.io.File("pipeline.yaml"));

JUnit 5 Integration Test

import org.giwi.nifi.tester.NiFiConnection;

@NiFiConnection(url = "https://localhost:8443/nifi-api",
                 user = "admin",
                 password = "admin1234567")
class MyIntegrationTest {

    @Test
    void testDeploy() {
        PipelineManager tester = new PipelineManager(getClass());
        PipelineManager.PipelineManagerResult result =
            tester.deployPipeline(new java.io.File("pipeline.yaml"), "root");
        assertTrue(result.isSuccess());
    }
}

CLI Reference

OptionDescription
--url <url>NiFi API URL (default: https://localhost:8443/nifi-api)
--user <u>NiFi username
--pass <p>NiFi password
--file <path>Path to YAML pipeline file
--parent <id>Parent process group ID (default: root)
--convert <path>Convert NiFi JSON export to YAML
--export <id>Export process group to YAML
--dry-runValidate without deploying
--save-template <n> <f>Save YAML as reusable template
--load-template <n>Load a saved template
--list-templatesList available templates

--config <u,u,p>Save config to ~/.nifi-tester.yml
